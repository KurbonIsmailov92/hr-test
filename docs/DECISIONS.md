# Архитектурные решения (ADR)

| № | Решение | Обоснование |
|---|---|---|
| 001 | Modular Monolith: один Laravel, одна БД PostgreSQL, модули в `app/Modules` | Требование ТЗ; проще эксплуатация, граница модулей через Actions и события |
| 002 | UUID (v7 в Laravel 12+, упорядоченные) как первичные ключи | Не перебираются (снижает риск IDOR), безопасны для интеграций |
| 003 | `Person` отдельно от `User`; кандидат и сотрудник ссылаются на `Person` | Один человек может быть кандидатом, затем сотрудником, без дублирования ПДн |
| 004 | RBAC на `spatie/laravel-permission`, доступ к областям через разрешения (`admin.access`, `portal.access`, `candidate.access`), а не через имена ролей | Роли можно менять без правки маршрутов |
| 005 | Только логин и пароль, без 2FA/SSO (решение заказчика для MVP) | 2FA в backlog; компенсируется rate limiting, политикой паролей, аудитом |
| 006 | Email хранится в нижнем регистре, уникальность по `lower(email)` | Исключает дубли `A@x` и `a@x` |
| 007 | `audit_logs` только на добавление (триггер БД блокирует UPDATE/DELETE) | Неизменяемость журнала критических действий |
| 008 | Сброс пароля и вход не раскрывают, существует ли email и заблокирован ли пользователь | Защита от перебора учётных записей |
| 009 | Лэйаут Inertia выбирается по префиксу страницы (`Auth/`, `Careers/`, `Candidate/`, `Portal/`, `Admin/`) | Единая точка настройки трёх интерфейсов |
| 010 | Тексты интерфейса в `resources/js/locales/*.json`, серверные в `lang/*` | Требование: тексты не зашиты в компоненты; RU основной, TG обязателен, EN подключаемый |
| 011 | Ziggy не подключается, пути фронтенда в `resources/js/routes.ts` | Меньше зависимостей; соответствие путей проверяется тестами |
| 012 | Хостинг MVP: локально (Docker) и демо-стенд на бесплатном Render с тестовыми данными | Бесплатный Render: засыпание, эфемерная ФС, БД с ограниченным сроком и без бэкапов, Redis без персистентности |
| 013 | Согласие на обработку ПДн фиксируется (версия, время); версия `draft-0` | Юридический текст и требования законодательства РТ не утверждены и требуют проверки юристом |
| 014 | SSR для Inertia отложен на Этап 3 (Career Portal, SEO) | Не нужен для закрытых интерфейсов, снижает сложность Этапа 1 |
